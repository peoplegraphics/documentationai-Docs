`@panelwave/player` is the **open-source player** of the PanelWave ecosystem: an MIT-licensed **Angular library** (Angular 20; 21 and 22 from player 1.2.0 — see [Installation](/player/installation#requirements)) that renders interactive graphic novels from a [PanelWave manifest](/concepts/manifest) (`panelwave.json`). You embed it in your own Angular application; it takes care of rendering, navigation, localization, and reader controls.

<Callout kind="info">
The player renders whatever a valid manifest describes — it contains no authoring features. Works are created with the [PanelWave CMS](/cms/overview) or any tool that produces a manifest conforming to the [PanelWave Schema](/schema/overview).
</Callout>

## What it renders

A PanelWave work is a set of chapters whose **panels are nodes in a directed graph**. The player walks that graph, evaluating [JSON Logic](/concepts/graph-navigation) conditions on edges, and renders each panel from its layers:

- **Image layers** — the artwork itself, with lazy loading and caching.
- **Video layers** — video panels with play modes (`once`, loop, pingpong), start triggers (`on-view`, on click, …), and page-view sequencing.
- **Text and plugin layers** — text content and sandboxed iframe extensions.
- **Speech bubbles** — rendered by the `ComicBalloon` SVG engine with configurable balloon types, tails, and a styling cascade (work defaults → character override → per-bubble override).

Panels can be read one at a time (**panel view**) or composed into comic pages (**page view**) when the manifest defines page layouts.

## Feature summary

All of the following is implemented in the library source (`projects/player/src/lib`):

| Area | What you get |
|---|---|
| Navigation | Graph traversal with conditional edges and edge priorities (`FlowEngineService`), panel, page and [canvas](/player/canvas-view) view, a branch chooser for panels with several outgoing paths, keyboard and swipe input, autoplay with per-panel durations and video-aware advance |
| Localization | `LocalizedString` resolution with fallback chains, per-locale asset variants, runtime language switching, translated player UI via `@ngx-translate` |
| Variables | Five scopes (`global`, `chapter`, `page`, `session`, `persistent`), typed definitions, mutations, JSON Logic context building; `persistent` scope survives reloads via `localStorage` |
| Media | WebAudio mixer with four buses (`ambient`, `music`, `voiceover`, `sfx`), video controller with a single-active-video policy and stall watchdogs, LRU image cache, lookahead preloading |
| Monetization | Manifest paywall rules evaluated against an entitlement snapshot you supply (or fetch from your endpoint), work, chapter, panel and extras scopes, a paywall overlay with Buy / Subscribe options derived from the rule, in-player age gate, free-preview panels — checkout stays in your app |
| Analytics | Consent-aware `TrackingService` with event whitelisting, batching, and a configurable endpoint — driven by the manifest's `tracking` section |
| Extensibility | Plugin system: sandboxed iframe plugins with a capability model and a postMessage protocol, plus `plugin` layers inside panels |
| Accessibility | Keyboard navigation (Escape closes the open dialog), ARIA labels and roles throughout the UI, reduced motion from the OS setting, the reader's own setting or the host input, focus management in modals; an automated axe sweep covers every dialog, overlay and view |
| UI chrome | Toolbar (incl. like and bookmark), table of contents, settings modal, language modal, character roster, extras viewer, thumbnail strip, share modal, comments drawer, branch chooser — UI text in English and German; all icons are inlined Lucide SVGs (`pw-icon`), so the player adds **no icon-library dependency** |

## The main component

The component you embed is **`PlayerShellComponent`** (selector `pw-player-shell`). It orchestrates all services and child components:

```html
<pw-player-shell
  manifestUrl="/stories/my-story/panelwave.json"
  locale="en-US"
  [showToolbar]="true"
  (ready)="onReady()"
  (panelChange)="onPanelChange($event)">
</pw-player-shell>
```

See [Quickstart: Embed the Player](/player/quickstart-embed) for a complete working example and [Inputs & Outputs](/player/inputs-outputs) for the full API.

<Callout kind="alert">
The public API also exports a `PlayerComponent` with selector `pw-player` — it is a legacy stub and renders nothing useful. Always use `pw-player-shell`.
</Callout>

## Where it's used

- **Standalone reader sites** — any Angular application on a supported version that loads a published manifest and embeds `pw-player-shell`.
- **The demo application** — ships in the same repository (`projects/demo`), is the reference integration, and runs live at [panelwave.github.io/player](https://panelwave.github.io/player/). See [Demo App](/player/demo-app).
- **PanelWave CMS preview** — the CMS uses the player for its [preview environment](/cms/preview) so that what creators see is exactly what readers get. Rendering behavior lives in the player, not in a CMS fork.

## Project status

The library is **released**: version 1.0 is on npm as [`@panelwave/player`](https://www.npmjs.com/package/@panelwave/player), and new versions are published from the public [GitHub repository](https://github.com/panelwave/player) by its release workflow. It supports the format through 1.5. Every change runs through lint, the unit suite, a Playwright end-to-end suite (desktop and mobile) and a bundle-size budget of 180 KB minified + gzipped (about 106 KB today) — see [Development & Contributing](/player/development).

A few surfaces are still deliberately thin, and the pages in this section say so where it matters: the comments drawer and share modal are UI only (persistence is the host's job), and the manga-mode and high-contrast settings are stored but not yet applied.
