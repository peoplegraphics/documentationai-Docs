This page shows the smallest useful integration: point `pw-player-shell` at a manifest, and react to player events. It mirrors the demo application that ships with the player repository (`projects/demo`).

## Prerequisites

- [Installation](/player/installation) completed (`provideHttpClient()` + `TranslateModule.forRoot(...)` configured, UI translation files and balloon fonts added).
- A valid manifest file, e.g. `src/assets/my-story/panelwave.json`. You can export one from the [CMS](/cms/export), start from the minimal example below, or take one of the demo works from the player repository ([`projects/demo/src/assets`](https://github.com/panelwave/player/tree/master/projects/demo/src/assets): `sample-manifest.json`, `canvas-manifest.json`, `video-sequencing-manifest.json`).

## Option A: load by URL

The shortest embed: give the shell the manifest's URL. It fetches the JSON with `HttpClient`, validates it, and starts reading.

```typescript
// reader.component.ts
import { Component } from '@angular/core';
import { PlayerShellComponent } from '@panelwave/player';
import type { Panel, Chapter } from '@panelwave/player';

@Component({
  selector: 'app-reader',
  imports: [PlayerShellComponent],
  template: `
    <pw-player-shell
      manifestUrl="assets/my-story/panelwave.json"
      locale="en-US"
      [showToolbar]="true"
      (ready)="onPlayerReady()"
      (panelChange)="onPanelChange($event)"
      (error)="onError($event)" />
  `,
  styles: `:host { display: block; height: 100dvh; }`,
})
export class ReaderComponent {
  onPlayerReady(): void {
    console.log('Player is ready');
  }

  onPanelChange(event: { panel: Panel; chapter: Chapter }): void {
    console.log('Now showing panel in chapter', event.chapter.id);
  }

  onError(error: Error): void {
    console.error(error.message); // e.g. "Manifest load failed: …"
  }
}
```

A cross-origin manifest URL needs CORS headers on the server that hosts it (manifests published from the CMS preview send `Access-Control-Allow-Origin: *`).

<Callout kind="info">
The shell reads its inputs once, when it initializes. If both `manifestUrl` and `manifest` are set, the URL wins. To open a different work, re-create the component (see [Switching works](#switching-works)).
</Callout>

<Callout kind="alert">
**Known limitation (1.0.x):** the table of contents and the thumbnail strip read their chapter list from the `manifest` input, so they stay empty when the work is loaded with `manifestUrl` only. If your readers need them, use option B.
</Callout>

## Option B: pass the manifest object

Load the JSON yourself when you need to transform it first, cache it, or fetch it with your own auth — then bind the object:

```typescript
// reader.component.ts
import { Component, OnInit, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { PlayerShellComponent } from '@panelwave/player';
import type { PanelWaveManifest } from '@panelwave/player';

@Component({
  selector: 'app-reader',
  imports: [PlayerShellComponent],
  templateUrl: './reader.component.html',
})
export class ReaderComponent implements OnInit {
  private http = inject(HttpClient);
  manifest: PanelWaveManifest | null = null;
  error: string | null = null;

  ngOnInit(): void {
    this.http.get<PanelWaveManifest>('assets/my-story/panelwave.json').subscribe({
      next: (manifest) => (this.manifest = manifest),
      error: (err) => (this.error = `Failed to load manifest: ${err.message}`),
    });
  }
}
```

```html
<!-- reader.component.html -->
@if (error) {
  <p class="error">{{ error }}</p>
}
@if (manifest) {
  <pw-player-shell
    [manifest]="manifest"
    locale="en-US"
    [showToolbar]="true"
    (error)="error = $event.message" />
}
```

Either way that's the entire integration. The shell validates the manifest, navigates to the first chapter's graph entry panel (or to the reader's bookmark in this work, if they left one), and renders the viewport plus toolbar.

## A minimal valid manifest

The shell's `ManifestService` validates structure on load. At minimum it requires the `panelwave` header with a `version`, `meta` with `id`, `title`, `locales`, and `default_locale`, and at least one chapter with non-empty `panels` and a `graph` containing `entry` and `edges`:

```json
{
  "panelwave": {
    "version": "1.3.0",
    "schema": "https://panelwave.org/schema/1.0/panelwave.schema.json"
  },
  "meta": {
    "id": "work-hello-panelwave",
    "title": { "en-US": "Hello PanelWave" },
    "locales": ["en-US"],
    "default_locale": "en-US"
  },
  "assets": {
    "base": { "mediaBase": "assets/my-story/" },
    "catalog": [
      {
        "id": "img-1",
        "category": "image",
        "alt": { "en-US": "A quiet street at dawn." },
        "variants": [{ "src": "panel-1.webp", "mime": "image/webp", "w": 1280, "h": 720 }]
      },
      {
        "id": "img-2",
        "category": "image",
        "alt": { "en-US": "A door opens." },
        "variants": [{ "src": "panel-2.webp", "mime": "image/webp", "w": 1280, "h": 720 }]
      }
    ]
  },
  "chapters": [
    {
      "id": "ch-1",
      "title": { "en-US": "Chapter One" },
      "panels": {
        "p-1": { "layers": [{ "kind": "image", "id": "ly-1", "assetId": "img-1", "z": 0 }] },
        "p-2": { "layers": [{ "kind": "image", "id": "ly-2", "assetId": "img-2", "z": 0 }] }
      },
      "graph": {
        "entry": "p-1",
        "edges": [{ "from": "p-1", "to": "p-2" }]
      }
    }
  ]
}
```

For the full format, see the [manifest structure reference](/schema/manifest-structure) and [examples](/schema/examples). Validate manifests before shipping with the [CLI](/schema/cli).

## Starting at a specific position

Use the initial-position inputs to deep-link into a work (e.g. to implement resume — see [Saving Progress](/player/saving-progress)):

```html
<pw-player-shell
  [manifest]="manifest"
  [initialChapterId]="'ch-1'"
  [initialPanelId]="'p-2'">
</pw-player-shell>
```

An explicit initial position always wins over the reader's own [bookmark](/player/reader-interface#like-and-bookmark).

## Switching works

The shell loads its manifest in `ngOnInit` and does not watch its inputs afterwards. To switch to a different work at runtime, destroy and re-create the component — the demo app does this by clearing `manifest` (which removes the element via `@if`) before assigning the new one. With `manifestUrl`, wrap the element in `@if` or a keyed `@for` the same way.
