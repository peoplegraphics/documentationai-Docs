<Update label="2026-08-28" description="Format · 1.5.0 — asset folders & localization blocks" tags={["feature"]}>
  ## Schema 1.5.0: works that round-trip between authoring systems

  Format release **1.5.0** — additive as always, every existing manifest
  stays valid. Two new **authoring metadata** blocks let a complete work
  travel between authoring systems without losing organization or
  translation state (rendering consumers may ignore both):

  - **`assets.folders`** + per-asset **`folderIds`** — the asset
    library's folder tree (nested via `parentId`, ordered, n:m
    assignment). See [Assets](/schema/assets#assetsfolders--authoring-folder-tree-schema-15).
  - **Top-level `localization`** — the translation workflow state:
    locale list with default/active flags, and per-string entries with
    `defaultText`, per-locale values, stale markers, and
    machine-translation flags. Reader-facing text stays in
    `LocalizedString` objects as before.

  `@panelwave/types` and the [CLI](/schema/cli) are synchronized
  (validate + `upgrade` now target 1.5.0). These blocks are what the
  CMS's new [work archive transfer](/cms/export#archive-export) is
  built on. Details: [Versioning](/schema/versioning#what-changed-in-150).
</Update>

<Update label="2026-08-28" description="CMS · Work archive transfer & structure-tree precision" tags={["feature", "bugfix"]}>
  ## Move whole works between systems, and a structure tree that does what you drop

  An afternoon of transfer and editor work in the [CMS](/cms/overview):

  - **Work archive export & import** — a work can now travel as a single
    self-contained **`.zip` archive**: the manifest for **all** page
    formats plus every asset file (originals and all generated variants
    — nothing is re-transcoded on the other side), asset **folders**,
    and **translations**. Export it from the works list like any other
    [export format](/cms/export#archive-export), import it on any other
    PanelWave system or account via **Import Archive** on
    [My Works](/cms/import#importing-a-work-archive) — dev to
    production, between accounts, or as a full local backup. Imports
    are **atomic**, arrive as drafts with fresh ids, respect your
    plan's limits, and can be retried from the dialog if something
    goes wrong. Publish history, paywall configuration, analytics, and
    community data intentionally stay behind.
  - **Insert panels exactly where you want them** — the **Create New
    Panel** dialog gains a **Position** select ("At the beginning" /
    "After *panel*…", defaulting to the end), and dragging a panel from
    **Unassigned** onto a page now inserts it **at the drop position**
    instead of always appending — with the canvas renumbering
    immediately rather than after a browser reload.
  - **Deleting a shared panel no longer breaks other formats** — panels
    that appear on pages of several [page formats](/cms/works#output)
    are only **detached** from the page you delete them on; the other
    formats keep their copy. Creating panels from the tree also no
    longer corrupts existing page placements.
  - **Speech bubbles: move between panels, stay where lettered** — a
    bubble's right-click menu can now **move it to another panel**
    directly on the canvas, freshly created bubbles no longer vanish
    from page view until reload, and boosted balloons stopped drifting
    off their tails.
  - **Video panels behave** — a dropped video is recognized as the
    panel's background again (so the panel adopts its proportions), and
    the panel's **duration** syncs to the video's length on drop.
  - **Small but daily** — timeline footer actions are reachable in the
    collapsed timeline bar; timeline resizes grab the right panel;
    the canvas context menu correctly enables **Arrange / Duplicate /
    Delete** for the selected panel; and API validation errors now
    show *what* failed ("Placement #6: x must be between 0 and 1")
    instead of a bare "Validation failed".
</Update>

<Update label="2026-08-28" description="CMS · Page properties overhaul & editor reliability" tags={["feature", "bugfix"]}>
  ## Page backgrounds that publish, page ids that make sense, edits that stick

  An evening of page-properties and reliability work in the
  [CMS editor](/cms/editor/layout):

  - **Page Properties, reworked** — the dialog now looks and behaves
    exactly like Panel Properties: shared sections with persisted
    collapse state, and the page **title and chapter resolve through the
    current locale** (titles previously showed empty for BCP-47 locales
    like `en-US`). The production **Status** is a compact row of four
    colored buttons instead of a radio list.
  - **Page background colors that actually publish** — the background
    color picker works now: a curated preset palette for graphic-novel
    pages (paper whites, grayscale steps, sand/cream tones, soft
    pastels), custom colors by hex code, and a persisted Recent row.
    The chosen color renders on the canvas **immediately**, and the
    page's `visual` block now flows into published manifests — it was
    previously dropped, so page backgrounds never reached the
    [player](/player/overview). Along the way: saving page properties
    no longer fails when a value is cleared, and saved properties no
    longer vanish on reload.
  - **Format-scoped page ids** — pages in the manifest used to share one
    running counter across all [page formats](/cms/works#output), so
    the second format's pages started at `pg-41`. Each format now gets
    its own letter and counter: `pg-A1…pg-A17`, `pg-B1…pg-B13`, …
    Existing works pick the new scheme up automatically.
  - **Panel auto-fit in every format** — when a panel receives its first
    image or video, its proportions now adjust to the artwork in **all
    page formats the work supports**, not just the one you are viewing.
    The panel keeps its top-left position and only ever shrinks, so it
    always stays on the page; panels that already contain media are
    never resized by later drops.
  - **Panel-view edits always show up** — layers added or edited in
    [panel view](/cms/editor/canvas#page-view-vs-panel-view) now appear
    in page view right away (previously new images could stay invisible
    until a browser reload), and edits made moments before switching
    panels are saved first instead of being lost or written to the
    wrong panel.
  - **Asset library loads everything** — works with more than 50 assets
    showed only the newest 50 in the Assets tab (which also made
    deleting one asset look like it removed others). The full library
    now loads, folder counts refresh after a delete, and **deleting an
    asset also removes all its generated variants** (responsive sizes,
    thumbnails, posters, video renditions) from storage.
  - **A11y tab restyled** — the accessibility inspector now matches the
    other inspector tabs and works in dark and high-contrast themes.
</Update>

<Update label="2026-08-19" description="Format, Player & CMS · Panel variants go live" tags={["feature", "bugfix"]}>
  ## One panel, many stories — panel variants work end-to-end

  The format's conditional-content feature is no longer just a schema
  entry: variants authored in the CMS now publish into the manifest and
  actually render in the player. The same panel can resolve a conflict
  by committee for one reader and at high noon for another — or soften
  its artwork for readers below an age threshold.

  - **Selection rule codified** — variants are evaluated in manifest
    order and the **first** one whose JSON Logic `when` matches the
    current variables applies; overridden fields **replace** the base
    panel's values wholesale. Unknown or failing conditions count as
    false, so gated content fails closed. See
    [Panel Variants](/schema/variants#selection-order).
  - **Live in the player** — variants re-resolve the moment a variable
    changes (hotspot choices, edge mutations, host calls), and can swap
    layers, speech bubbles, hotspots, titles, even the panel's autoplay
    duration. Readers get an **Alt** toolbar button on panels with
    variants to cycle alternatives manually, plus an on-screen chip
    showing the active variant. See
    [State & Conditions](/player/state-and-conditions#variants).
  - **Trustworthy inputs for gating** — a new `initialVariables` player
    input (and the entitlement adapter's context) **seed variables at
    startup through a privileged path** that may populate `readOnly`
    definitions. Declare `user.age` read-only, seed it from your account
    system, and no in-story mutation or settings edit can ever change
    it. See [Inputs & Outputs](/player/inputs-outputs).
  - **Reader-editable preferences** — the settings modal's Variables tab
    is live: variables marked public (the default) and not read-only can
    be changed mid-read, with variants updating immediately — "EU style"
    vs. "US style" is one dropdown away.
  - **Authoring in the CMS** — the panel inspector's variant editor now
    speaks the format natively: a visual JSON Logic condition builder
    over your defined variables, typed override editors for titles and
    durations, and copy-from-panel seeding for layer/bubble/hotspot
    overrides. Publish validation flags duplicate variant ids, missing
    conditions, and references to undefined variables, and variant texts
    flow through translation extraction and write-back like any other
    localizable string.
  - **Fixed along the way** — published manifests previously **dropped
    variants silently**, and dot-namespaced variable ids like
    `path.choice` never resolved in any JSON Logic condition (this also
    affected conditional edges and `visibleIf`). Both work now.
</Update>

<Update label="2026-08-19" description="Player & CMS · Hotspots come alive + click heatmap" tags={["feature", "bugfix"]}>
  ## Hotspots now actually work — and you can watch readers use them

  - **Interactive hotspots in the player** — the hotspots you draw in the
    editor now render and act in the published work: readers see a gentle
    pulsing outline (respecting reduced motion), and activating a hotspot
    runs its action — **navigate** with variable changes and a transition,
    **set variables**, **open extras** at a specific item, **open a modal**
    with localized text, or **trigger a plugin event**. Fully
    keyboard-accessible with localized screen-reader labels, in panel and
    page view. See [the reader's view](/player/reader-interface#interactive-hotspots).
  - **Click heatmap in the analytics dashboard** — a new section shows
    *where* readers click on each panel as a cool-to-hot density overlay,
    with hotspot outlines, per-hotspot hit counts, and the **dead-click**
    share: taps that hit no hotspot, i.e. places readers expect
    interactivity. Reads raw clicks, so it updates without waiting for the
    nightly aggregation. See [Click heatmap](/cms/analytics#click-heatmap).
  - **Reading funnel & panel engagement documented** — the dashboard's
    per-panel drop-off funnel and views/dwell/bounce table now have
    [reference docs](/cms/analytics#reading-funnel).
  - **Editor fix** — hotspots are reloaded when you reopen a panel (they
    previously disappeared from the canvas after a reload while still being
    saved), and hotspot geometry is stored in the format's normalized
    coordinates so exports are always schema-valid.
  - **Tracking** — the player records `hotspot_click` events with normalized
    coordinates and a hit/miss flag, consent-gated and whitelisted like every
    other event. See [Tracking](/player/tracking#reading-session-and-hotspot-events).
</Update>

<Update label="2026-07-25" description="CMS & Player · Responsive image variants, account deletion" tags={["feature"]}>
  ## Right-sized artwork everywhere — and GDPR self-service

  - **Responsive image variants (CMS)** — the media pipeline now renders every
    image into a **WebP size ladder** (640 / 1280 / 1920 / 2560 px wide; only
    sizes below the original are created). Published manifests list the rungs
    as ascending variants while the full-quality primary file stays first, so

  - **Variant-by-zoom in the player** — panel and page view now pick the image
    variant by actual display size (container width × zoom ×
    devicePixelRatio, quantized, upgrade-only — no flicker back to
    thumbnails), completing the selection machinery canvas view shipped with
    format 1.4. Panel view additionally preloads the next panels along
    outgoing graph edges at the size they will render at, honoring
    `settings.preload`. See [Performance](/player/performance).
  - **Delete your account yourself** — the profile's Danger Zone gains a
    permanent **Delete account** action with typed confirmation: immediate
    deactivation and sign-out everywhere, then anonymization after a
    **30-day grace period** (support can cancel within the window). Works of
    teams where you were the only member go to the trash. See
    [Account & Team](/cms/account).
  - **Automatic data retention** — background housekeeping now deletes raw
    analytics events after 24 months (aggregated dashboard metrics are kept)
    and expired/revoked sessions after 90 days.
</Update>

<Update label="2026-07-24" description="Format 1.4.0 · The Infinite Canvas — schema, player & CMS" tags={["feature"]}>
  ## The infinite canvas: one continuous plane, a camera on the trail

  Format **1.4.0** brings the *infinite canvas* to the whole
  PanelWave stack: a chapter's panels can live on one continuous world-space
  plane, and the reader's screen becomes a camera that glides between them
  along the story graph. A single-column layout is a webtoon-style vertical
  strip; free 2D placement with camera trails is the full experience. All
  additive — works without a canvas are untouched, and print keeps using
  pages. See [The Infinite Canvas](/concepts/infinite-canvas).

  **Format (schema 1.4.0)** — all additive; see [Infinite Canvas](/schema/canvas):
  - **`Chapter.canvas`** — world-unit panel `placements` (1 wu = 1 CSS px at
    zoom 1; rotation, stacking, panel-relative `enterFraming`), `revealMode`
    spoiler protection (`always` / `on-approach` / `on-visit`), plane
    `background`, camera policy (`fitMode`, `overview`, `freeRoam`,
    `bounds`), and presentational `decorations` with parallax depth.
  - **`Edge.cameraMove`** — camera travel per graph edge: `direct` / `arc` /
    `waypoints` paths, `hold` / `pull-back` / `dive` zoom profiles, duration,
    easing, and a `reducedMotionFallback` transition. Inherits like
    `transition` via the new `FormatPreset.defaultCameraMove`.
  - **`FormatPreset.canvasView`** — per-format opt-in; players without it (or
    without canvas support) fall back to panel view.
  - `@panelwave/cli` validates the new semantic rules (placement keys must be
    chapter panels, performance budget, waypoint consistency) and its
    `upgrade` target is now synchronized at `1.4.0`.

  **Player** — a third view mode alongside panel and page view; see
  [Canvas View](/player/canvas-view):
  - Camera glides with authored paths and zoom profiles (motion-safety speed
    cap, interruptible by the reader), overview zoom (`O`), guided or
    free-roam input on touch, mouse, and keyboard.
  - Virtualized rendering (≤ 12 mounted panels regardless of chapter size),
    **variant-by-zoom** image selection (overview mounts thumbnails,
    close-ups load full resolution, upgrade-only — no flicker), and
    settle-time neighbor preloading honoring `settings.preload`.
  - Accessibility built in: no gliding under reduced motion (cross-fade
    reframes instead), full keyboard traversal, `aria-hidden`/`inert` on
    non-current panels, graph-driven reading order.
  - New embedding API: `viewModeOverride` input and throttled `cameraChange`
    output.

  **CMS** — a new authoring surface; see
  [Canvas Layout Board](/cms/editor/canvas-layout):
  - Spatial board with live panel artwork, graph-edge arrows, drag/resize
    with snap, align/distribute, and auto-layout presets (**vertical strip**
    for webtoon-shaped works, layered **graph layouts** for branching 2D
    canvases).
  - Camera-move inspector with **path ghosting** and draggable waypoints,
    **gap calipers** showing distance-as-time in beats, an **enter-framing**
    tool, per-panel reveal modes, and decoration authoring (opacity,
    parallax, rotation).
  - Work Properties → Output gains per-format **Infinite Canvas View**
    toggles; publish preflight validates canvas integrity; the
    [Preview](/cms/preview) tab's new **View** selector compares panel and
    canvas modes on the live manifest.
</Update>

<Update label="2026-07-12" description="Format 1.3" tags={["feature"]}>
  ## Format 1.3 — reusable style presets & implicit speech toggle

  Additive, backward-compatible release: every valid 1.0–1.2 manifest remains valid unchanged.

  - **Reusable style presets** — like CSS classes for the manifest. Named text
    styles in `settings.typography.textStyles` (referenced by
    `TextLayer.styleRef`) and named balloon presets in
    `settings.typography.balloonPresets` (referenced by
    `SpeechBubble.styleRef`). Shared styling is defined once and edited in one
    place; the balloon cascade becomes work → character → **preset** → bubble.
    Sample 11 replaced 104 identical caption style blocks and 79 repeated
    balloon overrides with one text style and six balloon presets.
  - **The speech toggle is implicit** — every speech bubble is inherently
    subject to the reader's speech toggle (initial state:
    `settings.ui.speechDefault`). The per-bubble
    `visibleIf: {"var": "prefs.speech"}` boilerplate is obsolete; `visibleIf`
    is reserved for story logic, and a forgotten boilerplate line can no
    longer make a bubble immune to the toggle.
  - **Player** — text layers and balloons resolve `styleRef` presets; the
    toolbar speech toggle is functional and seeded from `speechDefault`.
  - **CMS** — presets are exported with the manifest, `styleRef` round-trips
    through the editor, validation warns about dangling preset references,
    and legacy `prefs.speech` boilerplate is stripped on export.

  Details: [Settings](/schema/settings), [Speech Bubbles](/schema/speech-bubbles), [Layers](/schema/layers), [Versioning](/schema/versioning).
